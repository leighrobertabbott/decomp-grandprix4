# What people are doing (October 2026) - and what this repo took from it

Compiled 2026-10-02 from the projects' own repositories and write-ups. "From
your notes" marks material the user had already collected; everything else was
found and checked in this session.

## Agent-driven decompilation, by approach

| Project | Approach | What we took |
|---|---|---|
| **Thief3-Decomp** (Veradictus) - x86 MSVC 7.1, matching | Opus lead + Sonnet/Opus sub-agent swarms; claim -> context -> try -> accept/defer; size bands; guard hook; lead-owned integration, naming passes, exclusions; measured costs per band ([repo](https://github.com/Veradictus/Thief3-Decomp), `docs/agent-workflow.md`, `tools/agent/worker.md`) | the whole orchestration model: bands, protocol shape, one-line JSON summaries, guard, re-check claims under the lock, exclude library/compiler shapes, names between batches |
| Thief3 measured numbers | head band (<=31 bytes) 93-97% matched at ~20-36K priced tokens/match; main band 72-81% at ~71-105K; Opus big band 67-83% at ~97-205K; headless `claude -p` workers ~2M input tokens/match vs ~12.6K sub-agent start | sub-agents, not headless workers |
| **MW2** (momo5502 post-mortem, 2026-08-17) | 3 worker + 1 overseer agents, Discord/GitHub/CI, IDA/Ghidra MCP; ~7,000 commits, 5,588/16,324 functions (34%) in ~4 weeks, 199.8B tokens ([post](https://momo5502.com/posts/2026-08-17-mw2-decompilation/)) | one goal at a time; mechanical first; re-inject rules after compaction (SessionStart/compact hook) |
| **Burnout Paradise** BP-Decomp_Workflow (from your notes) | ledger states, dossiers, compile gate, glue/stub/instruction-shape audits, Xenia traces to scope goals ([repo](https://github.com/BurnoutDecomp/BP-Decomp_Workflow)) | dossier = context packet; `asmaudit` -> our shape gate; trace-scoped goals -> `runtime coverage-import` |
| **Klonoa: Empire of Dreams** (GBA, from zero to 51%) | Claude Code + asmlift (programmatic decompiler) + Transmuter (agent-friendly permuter) + gba-kit (scriptable emulator used for runtime naming; found a 25-year-old easter egg); adversarial review sub-agents; agents tried to "cheat" (forking the compiler, register pinning) ([write-up](https://gambiconf.substack.com/p/starting-a-decompilation-project)) | emulator as an agent tool; review against cheating; runtime evidence for names |
| **Mizuchi** benchmark | Claude Sonnet 4.6 in an m2c/permuter/objdiff pipeline: 74% of 60 functions matched; 88% of outcomes identical across runs; 49 duplicate-submission loops observed ([write-up](https://gambiconf.substack.com/p/can-llms-really-do-matching-decompilation), [repo](https://github.com/macabeus/mizuchi)) | refuse byte-identical resubmissions; "same compiled code as attempt N"; give agents the comparator's detail |
| **Snowboard Kids 2** (from your notes) | N64 matching with agents; 100% matched; recomp follow-up ([blog](https://blog.chrislewis.au/using-coding-agents-to-decompile-nintendo-64-games/)) | build-and-verify loop as the agent's only judge |
| **Chromatron recompiled** (Quesma, Feb 2026) | Windows XP x86 + PowerPC game -> Rust/Wasm with PyGhidra + Claude Opus 4.6; pixel-perfect only once a pixelwise comparator existed ([post](https://quesma.com/blog/chromatron-recompiled/)) | "LLMs are eager to say it's the same" -> every claim goes through an oracle |
| **LEGO Island / reccmp** | PC MSVC matching with source annotations (`// FUNCTION: <module> <addr>`), stack/vtable/data comparison ([repo](https://github.com/isledecomp/reccmp)) | annotation format, kept so a VC6 byte-matching track (T3) can be added later |
| **re3 / gta-reversed** (PC, long-standing) | DLL injected into the original exe, reversed functions hooked in one by one and toggled at runtime | `hook/`: dinput8 proxy, per-function toggles in `gp4hook.ini` |
| **libsm64 / G64** (from your notes) | decompiled subsystem exposed as a library, embedded in other engines | M5 `libgp4sim` endgame |
| Research | ICML 2026 "Matching Decompilation as a Verifier-Guided Task for Human-Centered Coding Agents" (harness: diagnostics, ranking, run history, bounded variant search, commits gated on verifier improvement); Echo ([arXiv 2609.18706](https://arxiv.org/abs/2609.18706)); Decaf ([arXiv 2605.11501](https://arxiv.org/pdf/2605.11501)); RlDecompiler (ICPC 2026) | gates as the only acceptance path; ranking easy-first; run history in the ledger |
| Agent RE tooling | Ghidra MCP servers (GhidraMCP, kawaiidra-mcp, ~200-tool servers), IDA Pro MCP, REA (CLI + MCP), e5r and Vibe RE (from your notes), Universal Modder (recon/RE skills, mashups; from your notes) ([universal-modder](https://github.com/rehan-remade/universal-modder)) | packets are generated by our own analyzer so workers need no MCP; Ghidra is optional context |

## The wider wave (what the Pirat_Nation post was pointing at)

Pirat_Nation's 2026-10-01 post: AI developments are speeding up game
decompilation; several projects reached 100%; most use agents for parts of the
work ([post](https://x.com/Pirat_Nation/status/2105568897361477685)). Same feed:
Twilight Princess 100% decompiled, GoldenEye 100% after ~5 years, Mario Kart Wii
natively recompiled for PC with AI used for parts of the code, and a Donkey Kong
64 team announcing early because a rival recomp relies on AI "vibe coding". The
quality debate is real; the answer every serious project converged on is a
mechanical oracle.
